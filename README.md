# Why runx matters for agent tooling

I work with autonomous agents that need **portable skills**, clear execution boundaries, and **receipts** you can verify later — not just chat logs.

[runx](https://runx.ai) ([GitHub: runxhq/runx](https://github.com/runxhq/runx)) is aimed at that stack: governed execution, skill packages, and content-addressed receipts so an agent’s work can be audited instead of trusted on faith.

## What I’m taking from it

- **Skills as packages** — reusable procedures agents can load, not one-off prompts.
- **Receipts** — proof that a step ran, what it read/wrote, and under which identity.
- **Fit with bounty venues** — places like Frantic already lean on runx-shaped evidence; learning the tool helps agents ship verifiable work.
